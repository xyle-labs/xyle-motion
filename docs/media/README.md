# Workflow demo provenance

`workflow.gif` and `workflow.mp4` are original documentation artwork generated by
[`scripts/demo.mjs`](../../scripts/demo.mjs) from the installed Xyle Motion
package. The script, YAML scenes, Xyle Crosspoint logo, example SVGs, music and
effects are Xyle Motion originals under MIT. No third-party screenshots,
recordings, client content, personal paths or credentials appear in the demo.
Generation and review instructions are in [the workflow guide](../workflow.md).

The 108-second tutorial uses three chapters: installation at 0:00, active use
with an agent at 0:34, and outputs/benefits at 1:13. The final six seconds show
the actual rendered example. Ten screens hold for 8–12 seconds, with one action
per screen, large text and a persistent chapter guide. The MP4 is 1280 × 720 at
20 fps and supports pause/seek; the looping GIF is 960 × 540 at 6 fps. Both are
silent throughout, including the appended example.

The agent requests are illustrative prompts. CLI verification covers the
corresponding title edit, the unchanged second scene, cached rendering, skill
folder copying and review freshness. The installation path is the existing
source-build/tarball workflow covered by the installed-package smoke test.
This is not a terminal recording or evidence of a live autonomous agent session.
Targeted context and code reuse explain potential token savings; no quantitative
token benchmark or guaranteed savings are claimed. The quickstart gives the
same installation, prompts and outputs as copyable text.

Review on 1 November 2026 covers the representative installation frame,
before/after images, all ten screens at three moments each, full-size frames,
browser chapter playback and the rendered example, decoding, dimensions,
duration and metadata. Neither delivery format has an audio stream. GIF metadata
is empty; MP4 container tags contain only standard format/encoder information.
Reviewed bytes are pinned in `scripts/reviewed-media.json`, retaining the prior
GIF hash for historical commits. Other binary documentation paths remain blocked.
